100-Point Scoring Rubric

RepoLens uses a 100% deterministic, rule-based grading engine. Zero machine learning or external LLMs.

Important Principle: This score measures repository hygiene, engineering practices, safety, and documentation standards — not code quality or algorithmic correctness. High scores signify clear documentation, tests, CI/CD automation, open-source licensing, and clean safety practices.
1. Documentation & Discoverability
25 Points Max
  • README Presence: Root README.md exists explaining the project 20 pts
  • README Substance: Detailed README exceeding 200 characters 4 pts
  • Installation & Usage: Headings for installation, setup, or quickstart 5 pts
  • Demo Visuals: Architecture diagram, screenshot, or demo GIF in README 2 pts
  • Repository Description: Non-empty GitHub summary description 2 pts
  • Topics & Tags: At least 1 discoverable GitHub topic tag 2 pts
2. Licensing & Community Standards
10 Points Max
  • Open Source License: Standard LICENSE file (MIT, Apache, GPL, BSD, etc.) 5 pts
  • Contribution Guidelines: CONTRIBUTING.md guide for community contributions 3 pts
  • Issue / PR Templates: Standardized bug report and PR templates in .github/ 2 pts
3. Maintenance & Commit Activity
20 Points Max
  • Push Recency: Commit pushed within the last 180 days (graded up to 365 days) 8 pts
  • Commit Frequency: History with multiple commits demonstrating sustained development 6 pts
  • Active Project Status: Repository is actively maintained (not marked as archived) 6 pts
4. Engineering Hygiene
25 Points Max
  • Automated Test Suite: Test directories (src/test/, tests/, etc.) or test source files 10 pts
  • CI/CD Automation: Continuous Integration workflow files in .github/workflows 7 pts
  • .gitignore Configuration: Proper ignore manifest preventing repository bloat 4 pts
  • Build Manifest: Standard build descriptor (pom.xml, package.json, requirements.txt, etc.) 4 pts
5. Safety & Secret Prevention (Trie & KMP)
15 Points Max

Evaluated deterministically via our hand-crafted Trie and Knuth-Morris-Pratt (KMP) substring matchers on file paths and README text. Does NOT clone repository contents or fetch private files.

  • No Committed .env Files: Clean from real .env or credentials files (templates like .env.example are allowed) 5 pts
  • No Committed Private Keys: Clean from SSH / RSA private key files (id_rsa, id_ed25519) 5 pts
  • No Committed Dependencies / OS Junk: Free from node_modules/, .DS_Store, or build output directories 5 pts
6. Repository Structure & Layout
5 Points Max
  • Sensible Layout: Uses organized code directories (src/, lib/, app/) rather than a flat root dump 3 pts
  • File Size Standards: Free from single massive binary or data files exceeding 5 MB 2 pts
